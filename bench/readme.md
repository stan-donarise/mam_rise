# Rise benchmarks

В каталоге: «Сущности» и «Текст» (`$giper_baza_text`).
В «Сущностях» выбирается хранилище: Гипербаза (одна Area на запись)
или IndexedDB через `$mol_db`, без индексов. Прогоны обоих движков
показываются в одной таблице со столбцом «Хранилище».
По умолчанию — 100 записей / строк и 4 свойства.

## Изоляция и результаты

Нагрузка выполняется в iframe `?rise_fixture=goods|text|idb`.
В iframe таблица или редактор, без меню и заголовка страницы.
Поиск, фильтры и ручные действия находятся над данными внутри iframe.
Параметры и запуск находятся во внешней панели;
команда запуска передаётся через проверенный по origin/source `postMessage`.
Только там итоговый выбор серверов Гипербазы заменён на пустой список:
ни seed, ни URL не могут включить отправку тестовых данных.
Замер F5 действительно перезагружает iframe. Demo также открывается
в отдельном offline iframe.

У внешней страницы отдельная native IndexedDB `$rise_results`, у нагрузки —
`$rise_workload_<kind>`. Старый `$giper_baza_mine` не открывается:
накопленные тестовые данные не попадут во внешний синхронизатор.
Нагрузка IDB использует отдельную базу на каждый прогон.

Общий Land результатов — `CdQsmv8O_YAqIGknH`.
Всем разрешена запись данных (`post/just`), но не изменение прав.
Подписанный публичный grant в `archive/seed` позволяет начать локальную
запись в чистом профиле, не скачивая права с настоящего сервера.
Он не содержит секретного ключа и не меняет выбор серверов.
Строка — отдельный JSON-атом по ключу `<kind>:<uuid>`; повторная доставка
не добавляет дублей. Внутри только замеры, дата, состояние и версии.
Параметры компьютера и браузер сохраняются снимком на момент запуска;
в таблице открываются штатным `$mol_pick`. Старые результаты без них совместимы.
Для текста сохраняется размер UTF-8 (КБ = 1024 байта), включая добавленный символ.
История ограничена примерно десятью видимыми строками с внутренней прокруткой.
Переключатель в шапке выбирает таблицу (по умолчанию) или графики.
Графики используют только текущую версию бенчмарка и показывают медиану на каждый объём, не смешивая хранилища,
число полей, компьютеры, браузеры и версии бенчмарка/движка.
Данные записей, текст, ссылки на тестовые Lands и имя тестовой IDB
во внешний документ не передаются.

Внешняя страница проверяет origin, окно отправителя и схему результата.
Перед записью сохраняет маленькую очередь в localStorage; после локального
IDB commit очищает её. При ошибке доступно «Повторить сохранение»;
очередь восстанавливается после F5. Доставка — штатная CRDT-синхронизация:
«Результаты сохранены» не означает подтверждение сервером.
SessionStorage внутри нагрузки нужен для продолжения замера F5,
а не как общее хранилище результатов.

## Серверы и версии

Внешняя страница использует штатный выбор: URL override, каталог `web.baza`,
native fallback. В `test.html` сохраняется override `localhost:9090`
из `giper/baza/yard/yard.test.ts`.
`bench/seed` удерживает Lands seed-пакета до создания живых потребителей
адресов. Исходники `giper/**` не изменяются.

Методика — `0.3.0`, Гипербаза — полный фиксированный коммит
`2e6100b225c8d4fb3a5b5d14e8568223e8a8c785` (для IDB — «—»).
Версии фиксируются при создании прогона и сохраняются после F5.
У старых локальных строк без версий отображается «—».
Константы в `bench/run/run.ts` нужно обновлять при смене методики
или зависимости. В таблице хеш сокращён до восьми символов.

## Границы замеров

Все времена в секундах, три знака. Ручные действия не создают прогон.
Сущности: создание, полный поиск по названию, добавление одной записи,
F5 до появления первой строки и первый поиск после F5. Без индексов.
Гипербаза: таймер заканчивается возвратом native API операции;
дренирование подписей и IDB-записей вынесено между замерами.
IDB: запись завершается после native transaction commit, поиск читает
записи целиком. Это сравнение путей API с разными гарантиями сохранения,
а не чистой скорости одного диска.

Текст: вставка, появление одного символа в начале видимого текста,
F5 до восстановления текста в textarea. «Очистить» создаёт новый Land,
а не удаляет содержимое тяжёлого прежнего Land.

## Проверки

```sh
node rise/bench/baza/goods/playwright/goods-render.js
node rise/bench/baza/crdttext/playwright/crdttext.js
node rise/bench/archive/playwright/archive.js
node rise/app/playwright/startup.js
node rise/bench/idb/playwright/large.js
node rise/bench/host/controls/playwright/textarea.js
```

Первые два сценария используют offline-каталог `?rise_fixture=tests`,
проверяют настоящие операции/F5 и отсутствие попыток подключения.
`RISE_TEST_URL` задаёт опубликованный URL.

Третий прогоняет три нагрузки, записывает реальные результаты в общий Land,
проверяет параметры компьютера, графики, фильтры, сброс и адаптивность.
Локально используется `test.html` и только `localhost:9090` (без реальных серверов).
`RISE_ARCHIVE_URL` задаёт опубликованный URL: там дополнительно проверяются
чтение и запись независимым профилем и отсутствие тестовых Lands в сетевых пакетах.
Все браузеры временные, со сроком выполнения и finally-очисткой.
Приложение и сценарии самостоятельны: зависимостей от `shm` нет.
Скриншоты сценариев находятся в игнорируемой папке `rise/-test-results`.

### Тестовый интерфейс и unit-тесты

В Baza `2e6100b` тест `Land Area inherits rights` может зациклиться
на создании Area и исчерпать память даже без запуска бенчмарка.
Заодно исполнение сотен unit-тестов рядом с нагрузкой искажает измерения.
Поэтому `app/ui.web.test.ts` отделяет обычный `test.html` (UI + hot reload)
от явного `test.html?rise_unit_suite=1` (оригинальный unit-набор).
Все исходные функции сохранены в `rise_app_test_suite`, ничего не заменяется
пустыми успешными тестами. В консоли явно указано: отложенные тесты **не
считаются прошедшими**. В UI автоматически выполняется только проверка
сохранения отдельного набора. Сценарий `app/playwright/startup.js` проверяет
три чистых профиля, ограниченный heap и отсутствие запуска unit-набора в iframe.
Полный сторонний набор пока содержит указанный дефект: запускать его нужно
отдельно, с ограничением времени/памяти. Исходники `giper/**` не менялись;
это изоляция тестов, **не исправление движка**.
